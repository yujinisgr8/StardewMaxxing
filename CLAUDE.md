# CLAUDE.md — StardewMaxxing

A Stardew Valley income optimizer. Enter an item → ranked table of every processing route with
sell value + gold/day, best highlighted. Bilingual EN/简体中文. **Two apps, one engine:** a local
Electron macOS app and a SwiftUI iOS app, both driven by the shared core in `shared/`.

**Read `PROGRESS.md` first** — it holds the live task checklist and the current state/next step.

## Stack
- **Desktop:** Electron + Vite + React + TypeScript, Tailwind CSS; light state via React state/Context.
- **iOS:** SwiftUI, iOS 17+, no third-party dependencies.
- Game data bundled as static JSON → both apps are fully offline.

## The shared core — `shared/` (read this before touching the engine)
`shared/` is the contract between the two apps. **Rules are data, not code:**
`shared/machines.json` holds all 10 machines / 31 rules (every formula, time, multiplier), and
BOTH engines are thin interpreters of it. A wiki correction is a JSON edit that lands in both
apps — do NOT hardcode a formula in `machines.ts` or `Compute.swift`.

| File | What it is |
| --- | --- |
| `machines.json` | the machine rules (predicate → output id, EN/zh name template, value, batch, minutes, flags) |
| `items.json` | 217 items, roe already derived at build time, each with an `uses` block |
| `sprites/*.png`, `fonts/Zpix.ttf` | art & pixel font, bundled by both apps |
| `fixtures/parity.json` | golden engine output — both test suites assert against it |

**Parity is enforced, not hoped for.** `npm run verify` (TypeScript) and `npm run verify:ios`
(Swift) both check the same `fixtures/parity.json`. If you change engine behaviour deliberately,
regenerate with `npm run build:fixtures` and review the diff. Two traps the Swift side handles
explicitly: JS `Math.round` rounds halves toward +∞ (Swift uses `jsRound()`), and JS's sort is
stable while Swift's is not (ties break on original machine order).

## Source of truth
**https://stardewvalleywiki.com and its child pages** are authoritative for all prices,
formulas, batch sizes, processing times, and names (incl. official zh-Hans via the wiki's
Chinese pages). If memory disagrees with the wiki, the wiki wins. Each generated item carries
a `source` URL.

## Core formulas (encode exactly per wiki; verify against the machine pages)
- **Keg:** fruit→Wine `base×3`; veg→Juice `round(base×2.25)`; specials Hops→Pale Ale,
  Wheat→Beer, Coffee Bean×5→Coffee, Honey→Mead, Tea Leaves→Green Tea, etc.
- **Preserves Jar:** fruit→Jelly `2×base+50`; veg→Pickles `2×base+50`; roe→Aged Roe.
- **Dehydrator:** fruit→Dried Fruit `7.5×base+25` (×5 batch); mushroom→Dried Mushroom; Grapes→Raisins.
- **Cask:** ages Wine/Beer/Mead/Pale Ale/Cheese/Goat Cheese → iridium `×2`.
- **Fish Smoker:** fish→Smoked Fish `×2`.
- **+ Sell raw** baseline.

## Modifiers (Settings)
- **Professions = the in-game Farming skill tree**, not free toggles. `Settings.level5`
  (`'none'|'rancher'|'tiller'`) is one mutually-exclusive Lvl-5 pick; `Settings.level10`
  (`'none'|'artisan'|'agriculturist'|'coopmaster'|'shepherd'`) branches off it. Only three affect
  sell value: **Tiller +10%** (raw crops & flowers), **Rancher +20%** (raw animal products —
  milk/egg/wool/truffle; *processed* animal goods are Artisan, not Rancher), **Artisan +40%**
  (artisan goods). Agriculturist/Coopmaster/Shepherd are growth/production-speed only → no price
  effect (shown in the UI, labeled informational). Each route carries `artisanGood`/`tillerEligible`/
  `rancherEligible` flags; `priceRoute` derives the active professions from the tree.
- Input quality (normal/silver×1.25/gold×1.5/iridium×2) → raw sale & cask only; kegs/jars/
  dehydrator normalize to base quality.
- Ranking metric: total gold (per-input value, fair across batch sizes) vs gold/day.
- **gold/day uses whole-day occupancy:** `effectiveDays = ⌈rawMinutes / 1600⌉` (machines are
  emptied/refilled each morning, so a job ties one up for whole "collect next morning" days —
  Wine 6.25→7d, sub-day machines →1d, Dehydrator stays 1d). gold/day = per-input value ÷ effectiveDays.

## Wiki gotchas encoded in the rules
- **Forage needs positive energy.** The Preserves Jar and Keg accept "any *positive energy*
  Forage" — Daffodil restores 0 energy and is therefore rejected by both. `build-data.ts` parses
  the infobox Energy value and tags such items `zero_energy`; the rules gate on `notTag`.
  When parsing the infobox, strip `<style>`/`<script>` blocks FIRST — their CSS text survives
  naive tag-stripping and sits between the "Energy / Health" label and its number.
- The Jar excludes **Red Mushroom** (negative energy); the rule carries `notTag: red_mushroom`
  even though no such item is in the catalog yet.

## "Other uses" data (`ItemUses`)
Each item carries `uses`: `bundles` (standard Community Center only — **Remixed Bundles are
deliberately excluded**, since the zh wiki doesn't mirror them and most saves don't use them),
`lovedBy` (villagers who LOVE it — 8× friendship), `recipes` (dishes/crafts it's an ingredient
in) and `quest` (Help Wanted reward). Every name is bilingual.

Two parsing traps, both handled in `scripts/uses.ts` — keep them in mind if you touch it:
- The **zh bundle sentence puts the ROOM first** where English puts the bundle first, so the two
  are classified by content (a zh bundle name ends in 收集包), never by position.
- The zh wiki splits the recipes heading four ways (配方 / 食谱 / 烹饪 / 打造); English is always
  "Recipes". Villager zh names come from each villager's own page, not from row order.

## Run
- Dev (desktop): `npm install && npm run dev`
- Refresh data: `npm run build:data` (re-scrapes the wiki, rewrites `shared/`)
- Verify everything: `npm run verify:all` (TypeScript tests + Swift parity)
- Package (macOS): `npm run build && npm run package`
- iOS: open `ios/StardewMaxxing.xcodeproj` and Run, or
  `xcodebuild -project ios/StardewMaxxing.xcodeproj -scheme StardewMaxxing -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPhone 17 Pro' build`
  Installing on a physical iPhone needs a signing team set on the target (a free personal team
  works; its certificate expires every 7 days, so re-build weekly).
